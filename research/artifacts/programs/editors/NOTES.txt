0. HEADLINE CORRECTIONS TO THE MUSEUM METADATA

- [V] EDIT.EXE and EDITOR.EXE are NOT "the same editor in two GUIs". They are two independent implementations:
  0 of 124 EDIT functions share an opcode sequence with EDITOR's 30 user functions (fnhash.py). Different limits
  (EDIT 500 lines x 255 chars, tab=8 spaces; EDITOR 600 lines x 204 chars, tab=6 spaces), different style
  (EDIT = C++ classes with virtual methods; EDITOR = procedural C compiled as C++).
- [V] EDIT.EXE ("EDIT-TEST Ver 1.00") is built on the Digi-Test (DIGI_T/MAIN.EXE) GUI code base: 89 of 124 user
  functions (12,674 of 17,393 instructions, 73%) have opcode sequences identical to functions in MAIN.EXE; 82 of its
  116 strings are also in MAIN.EXE, including dead circuit strings ("NODE CTRL N", "VCC CTRL V", "DETECT FAULT",
  "IC TESTER", "TRUTH TABLE", "make a dectionary") and the five group-member names (Ebrahim El Etr, Hatem Moustafa,
  Khaled Zakaria, Mohamed Asaad, Yasser Mohamed). Only 3 strings are EDIT-only: "Name To Save/Load",
  "About This Program   << EDIT-TEST  Ver 1.00 >>", "NONAME.TXT". One whole segment (02D1, 22 functions, ~7.7 KB)
  is unique: the text-editor class.
- [V] needsArabart:true is wrong for EDIT.EXE, EDITOR.EXE and WINKEY.EXE. No INT 10h AH=36h anywhere in user code;
  E2E runs (typing, menus, dialogs, load/save) issued only INT 10h AH = 00,08,0F,10,12,1A (BGI driver). WINKEY has
  no INT 10h except mode set 10h. None of the three displays Arabic.
- [V] WINKEY is not pure Assembly: Turbo C++ 1.0 ("Turbo C++ - Copyright 1990 Borland Intl." at DGROUP), small model,
  main() is compiled C; the graphics library routines are C functions whose bodies are inline assembly (see 6).
- [V] WINKEY is non-interactive: no keyboard or mouse calls at all (no INT 16h/33h, no INT 21h key functions);
  E2E run with zero keys runs to completion and exits (AH=4Ch).
- [V] Neither editor uses a mouse (no INT 33h). Keyboard only, via bioskey() (INT 16h).
